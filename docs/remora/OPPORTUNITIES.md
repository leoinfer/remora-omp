# Ranked optimization opportunities

Ranks are hypotheses, not measured wins. Impact describes plausible end-to-end task productivity upside if the cause is present; confidence describes evidence that the issue affects this workload, not certainty the technique works. No opportunity is approved for product code until the baseline profile identifies the corresponding cost.

| Rank | Opportunity | Expected impact | Effort | Risk | Confidence | Evidence / next discriminating experiment |
|---:|---|---|---|---|---|---|
| 1 | **Instrument critical path and remove repeat inference**: correlate task/run spans, provider calls, tool activity, retries, compactions and Strata request counters; identify wasted calls/tokens before touching runtime. | Potentially high if repeated calls, retries or polling dominate; otherwise small. | Low–medium | Low | High that instrumentation is needed; low that it reveals a large win. | OMP already has optional agent telemetry and detailed run summaries. Collect per-task records; look for duplicate semantic requests, failed/replayed outputs and low-value follow-ups. |
| 2 | **Validate end-to-end stable prefix and Strata cache reuse** across unchanged system/tool prefixes and tool-result turns. | Potentially high for long prompts/repeated turns if prompt-read dominates; zero when cache already hits or tools invalidate prefix. | Low for audit/offline test; medium for adapter changes. | Medium: output serialization/model template/context changes can break correctness or merely move cache identity. | Low–medium. | OMP already has `AppendOnlyContextManager`; local provider routing auto-enables it by default. Strata's tokenizer reuses recent rendered-text prefixes, while the engine resumes only on exact token/image-prefix matches. The inspected matching path does not consume `AgentOptions.promptCacheKey`. Compare exact rendered token prefixes through tool cycles and correlate `reused`/`prompt_read` with saved task wall time before proposing any cache shim. |
| 3 | **Schedule independent work around local inference without GPU oversubscription**: overlap CPU/IO tools and cloud-only delegation while local GPU is occupied, using explicit resource admission. | Medium where valid independent work exists; none for dependency-heavy tasks. | Medium | Medium–high: extra concurrency can consume 32-GB RAM, saturate 8-core CPU, increase cloud cost, or contaminate measurements. | Low. | OMP already supports task batches, async jobs and concurrency limits. Measure idle gaps and CPU/RAM pressure, then compare bounded schedules only after a no-contention baseline. |
| 4 | **Reduce task/tool prompting and output tokens without dropping context** using task decomposition/answer contracts, compact but sufficient tool results, and verification-guided stopping. | Medium or high when token count or repeated reasoning is large; model-quality risk is central. | Medium | High correctness risk. | Low. | OMP already has cache-aware output pruning, stale-read superseding and stable append-only context; its content-addressed blob store is not a generic tool-result cache. First measure duplicate-call/tool-result tokens per verified task. A reuse layer needs exact workspace/environment identity and freshness semantics; semantic matches cannot substitute results. |
| 5 | **Local/cloud latency- and quality-aware routing** with explicit budgets and concurrent cloud delegation when local GPU is busy. | Workload-dependent; potential throughput gain if cloud resolves independent critical path without stealing local resources. | Medium–high | High: cost, availability, nondeterminism and quality variance; no guarantee cloud models are faster. | Low. | OMP already supports model roles, provider fallbacks and per-agent routing. A/B exact tasks with provider/model pinned; never compare different model quality as an unqualified speed win. |
| 6 | **Reduce provider event/serialization overhead or add backpressure**. | Low unless event queues or parsing show material CPU/memory cost relative to inference/tools. | Medium–high | Medium: streaming changes can alter responsiveness, cancellation and tool-call semantics. | Low. | `docs/provider-streaming-internals.md` documents immediate event forwarding and no hard provider backpressure. Profile event counts, queue growth and CPU before design changes. |
| 7 | **Persistent Rust worker / broader native core / zero-copy IPC**. | Potentially low for model-bound tasks, potentially higher for file/search-heavy workloads only if profiling shows JS/native boundary dominates. | High | High compatibility and maintenance cost; broad rewrite risks regressions in mature features. | Very low absent profile. | OMP already has roughly 80K LOC of Rust native components for hot-path filesystem, shell, AST, search, PTY and process facilities. Compare actual profiles and syscall/serialization cost before expanding Rust. |
| 8 | **Change Strata cache policy, GPU scheduling, prefill staging, expert residency or MTP.** | Potentially high but engine-specific; no harness-only result can establish it. | High | Very high (memory/VRAM, quality and active-session safety). | Low. | Source shows non-Metal MTP disabled by default, per-request draft threshold and offered/accepted counters; expert `DONE` fields count reads/bytes but do not isolate refill latency. Request-scoped `pcie_frac`, `prefill_pipe` and `aux_cpus` exist; prefill-pipe applies to layer splits. OMP's generic `compat.extraBody` can forward literal request fields, but lacks typed Strata controls/telemetry. Profile first, then test one variable in an isolated idle run. |

## Selection rule

First experiment: no optimization code. Capture per-run OMP events and Strata request telemetry for the same frozen task, then test the stable-prefix hypothesis against cache-reuse counters. The benchmark run determines whether a small context-serialization prototype is warranted. If existing append-only behavior already yields stable payloads and high reuse, reject that prototype and move to the measured dominant cost.
